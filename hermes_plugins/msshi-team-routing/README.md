# MSSHI native team routing

Hermes installs this local backend as `msshi-team-routing` as an available option. The user chooses their delegation backend in Hermes. MSSHI never sets or changes `delegation.backend`. Ordinary unnamed delegation passes through the user's existing delegation model/provider/reasoning/fallback settings. A task selecting the optional `profile` enum uses the real native bot's identity, skills and primary credentials via Hermes core.

Fresh MuZA setup with `--default-bot auto` uses the real `default` profile as Yukino and creates four named specialists. Existing layouts remain unchanged: a neutral default can cooperate with five existing named bots. The local `msshi-runtime/team-layout.json` maps logical roles to actual native IDs. `--default-bot keep-hermes` selects neutral default plus five named profiles; `--default-bot yukino` is an explicit conversion that preserves existing customized SOUL/configuration/history and hides a legacy named Yukino alias using a backed-up native tombstone. No profile data or model configuration is moved. Restoring a personal SOUL requires the separate explicit private-preset helper.

Before Hermes is configured, profiles and plugin files are staged. After each user configures their own model and provider in Hermes, `msshi desktop` or `msshi runtime migrate` can register the staged plugin. Selection of a delegation backend remains manual. Explicitly disabled plugins and custom delegation backends remain respected. Cooperation is contextual and bounded; simple conversation does not wake the whole team, and installation/structural checks do not call models.

Native Bot Chat `message_agent` remains preferred. This plugin does not invoke it, dispatch tasks, open apps, contact endpoints, or make model calls at install/startup. The bounded supported `register_system_prompt_section` API supplies role coordination to new session prompts regardless of cwd. Existing session prompts must be refreshed by starting a new session; a gateway restart reloads plugin discovery. AGENTS files remain a portable fallback.

Optional KAT is offered only to a running Shikaku session with a private, validated local opt-in. It is never applied to another bot or the primary model. No private config or keys belong in this repository.
